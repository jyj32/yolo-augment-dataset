## 一、启动

**双击 `run_gui.pyw` 即可。**

它会自动帮你做两件事：

1. 不弹黑色控制台窗口；
2. 如果当前的 Python 环境缺少 opencv / ultralytics 等依赖，会自动切换到装好的环境（通常是 conda 的 `yolov11`），不用你手动敲命令。

如果启动失败会弹窗告诉你缺什么，而不是闪退。

也可以改用命令行启动（等价）：

```bash
conda activate yolov11
python augment_gui.py
```

## 二、界面长什么样

窗口分四块：

| 位置 | 内容 |
|---|---|
| 左侧 | 所有参数（滑块 + 输入框 + 复选框 + 下拉框），分「基础设置 / 增强强度 / 触发概率」三组 |
| 右上 | 实时预览区（显示增强后的图，并画出标注框） |
| 右下 | 运行日志 |
| 底部 | 状态栏、五个按钮、自动生成的等价命令行 |

顶部还有一个「**预设**」下拉框，可以一键套用常用配置。

## 三、基本操作流程（四步）

### 第 1 步：选数据集（图片路径 + 标签路径）

界面里是**两个独立输入**，这是本次改版的重点：

| 输入项 | 含义 | 例子 |
|---|---|---|
| **图片路径**（`--image-path`） | 图片所在的目录 | `.../U2/images` 或 `.../U2/images/train` |
| **标签路径**（`--label-path`） | `.txt` 标签所在的目录 | `.../U2/labels` 或 `.../U2/labels/train` |

两者**可以完全不同位置**（不同盘、不同命名都行），因为很多标注工具导出时并不和图片放在一起。

- 点右侧「浏览...」选目录，或直接粘贴路径；
- 路径可以是绝对的，也可以是相对的（例如 `datasets/U2/images`）。

> [!TIP]
> **省事技巧**：只填好「图片路径」，然后点顶部的「**自动配对标签**」按钮。
> 它会自动把路径里的 `images` 换成 `labels` 填进去。仅当路径中含 `images` 目录时生效；
> 目录名不是 `images`（比如 `jpg_dir` / `ann_dir`）时会提示你手动选，不会瞎猜。

**要求**：

- 图片目录里要有 `.jpg/.jpeg/.png/.bmp` 等图片；
- 标签目录里要有**与图片同名**的 `.txt`（`A1.jpg` 对应 `A1.txt`）；
- 两者都支持平铺，也支持 `train`/`val` 子目录（会自动识别）。

> [!WARNING]
> **没有标注的图片无法扩充**。增强是把已有标注框一起做几何变换，没有框就没有东西可变换。
> 如果数据集只有图片，先用 X-AnyLabeling 标注，再用 `json2yolo.py` 转成 YOLO 的 txt（见文末）。

> [!NOTE]
> 工具会检查图片和标签是否**成对**。若图片明显多于标签（例如 160 张图只有 30 个 .txt），
> 会直接报错并列出缺标签的文件名 —— 因为标签路径填错时若不拦截，会生成一堆空标签图，
> 训练出来全是虚警。确实允许部分图片无目标时，加 `--allow-missing-labels`。

**输出目录**（`--out`）默认留空即可，规则是：

- 图片路径是 `.../U2/images` 或 `.../U2/images/train` → 输出到 `.../U2_aug`
- 其它情况 → 输出到 `<图片目录名>_aug`

想改也可以自己填。

### 第 2 步：选任务类型

「**任务类型**」（`--task`）下拉框：

| 选项 | 什么时候选 |
|---|---|
| `auto` | 默认，让脚本按标签列数自动判断 |
| `detection` | 普通目标检测（每行 `cls xc yc w h`，5 个数） |
| `segment` | 实例分割（每行 `cls x1 y1 x2 y2 ...`，多边形） |
| `obb` | 旋转框（每行 `cls x1 y1 ... x4 y4`，9 个数） |
| `pose` | **关键点检测**（每行 `cls xc yc w h` + K 组关键点，见下） |

> [!NOTE]
> 如果标签每行都是 **9 个数**，`auto` 无法确定是「旋转框」「4 点多边形分割」还是「1 个关键点」，
> 会报错要求你手动指定。这时按你是用什么方式标的来选：X-AnyLabeling 里画的是**旋转矩形**就选 `obb`，
> 画的是**多边形**就选 `segment`。

### 关键点（pose）任务的说明

关键点标签的格式是「目标框 + K 个关键点」：

```text
cls  xc yc w h   kx1 ky1 [kvis1]   kx2 ky2 [kvis2]   ...
```

前 4 个数是目标框，后面按 `kpt_shape` 依次排列 K 个关键点。关键点是**归一化**坐标。
可见性 `kvis` 取 `0`(未标注) / `1`(遮挡) / `2`(可见)，当 `kpt_shape` 第二维是 `2` 时不写这一列。

**数据集的 `data.yaml` 必须写明关键点数量**，否则无法解析：

```yaml
names: [pear]
kpt_shape: [5, 3]      # 5 个关键点，每个 3 维(x, y, 可见性)
flip_idx: [1, 0, 3, 2, 4]   # 左右翻转时的关键点编号映射（强烈建议提供）
```

| 字段 | 作用 | 不给会怎样 |
|---|---|---|
| `kpt_shape` | 关键点数量 + 维度（2 或 3） | 报错无法识别列数，必须手动 `--task pose` 且无法解析 |
| `flip_idx` | 左右翻转时对称关键点的编号互换 | 翻转后关键点**编号错位**（如左手 ↔ 右手点不交换），模型学到错误的解剖结构 |

> [!WARNING]
> **`flip_idx` 对 pose 极其重要。** 举例：人脸 5 点标注为 [左眼, 右眼, 鼻, 左耳, 右耳]，
> 左右翻转后"左眼"应变成图像右侧那个点，编号必须按 `flip_idx` 重排。
> 工具的 `--p-hflip` / `--p-vflip` 会按 `flip_idx` 自动重排；**若你的 yaml 没写 `flip_idx`，
> 工具会打印警告，此时建议把两个翻转概率都设为 0**。

增强时的关键点处理（已自动完成，无需干预）：

- 旋转 / 缩放 / 平移 / 透视：关键点与目标框用**同一个 3×3 矩阵**变换，严格对齐；
- 翻转：坐标镜像后按 `flip_idx` 重排编号；
- 关键点被转出画面：坐标置 `0` 且可见性置 `0`（Ultralytics 约定的"不可见"，不参与损失）；
- 目标框由**可见关键点的外接框**重新计算，因此旋转后框和点永远自洽。


### 第 3 步：统计 + 预览（重要）

点「**① 统计数据集**」：

状态栏会显示任务类型、类别、图片数、实例数、**空标签数**、以及预计生成多少张。这一步用来确认：

- 实例数如果不是 0，说明标注读到了；
- **空标签数**如果等于图片总数，说明这个数据集根本没标 —— 别往下点了；
- 预计生成数量对不对。

点「**② 预览原图**」：

右侧会显示一张用当前参数**实时增强**的图，**绿色框 = 检测框，黄色线 = 分割多边形**。

**这一步一定要看**，重点确认：

- 框有没有跟着图一起转、一起缩，是否还贴合目标；
- 有没有框被转出画面外（贴边是正常的，完全消失说明旋转角度太大）；
- 点「◀ 上一张 / 下一张 ▶」可以切换样本，多验证几张再往下走。

界面上改任何参数都会**自动**重新生成预览（约 0.5 秒延迟），不用反复点按钮。

### 第 4 步：开始增强

点「**③ 开始增强**」：

- 会先在后台跑，界面不会卡死，进度条转动，日志实时输出；
- 如果输出目录已存在，会先弹窗问你是否覆盖（选"是"会自动带上 `--overwrite`）；
- 如果检测到数据集没有任何标注，会再警告一次。

**增强完成后**，点「**预览输出数据集**」可以直接在右侧查看**已经生成的增强结果**：

- 显示的是输出目录里真实的文件（`images/train` 里的图片 + 对应 `labels/train` 的标注），
  而不是实时计算的预览；
- 文件名带 `_aug1` / `_aug2` 的就是增强图，可以和原图对比确认效果；
- 「◀ 上一张 / 下一张 ▶」在这一模式下切换的是输出数据集里的样本；
- 想看别的输出目录，改「输出目录」再点一次该按钮即可。

> [!TIP]
> 两个预览按钮的区别：
> **「② 预览原图」** = 按**当前参数**现场算一张，用来调参；
> **「预览输出数据集」** = 读**已生成的文件**，用来核对最终产物和标注是否正确。

## 四、参数怎么调

### 先选预设，再微调

顶部「预设」下拉框里有几套现成配置：

| 预设 | 适用场景 |
|---|---|
| **小数据集（55 张以内）** | 图很少，需要大幅扩充（约 6 倍），旋转/缩放较激进 |
| **工业零件（姿态固定）** | 零件摆放姿态固定，关闭左右/上下翻转，角度也小（约 3 倍） |
| **保守（只做颜色）** | 只调颜色亮度，不做任何几何变换（框绝不会偏） |
| **分割 + 复制粘贴** | 分割任务，开启 Copy-Paste |

选预设会保留你已经填好的路径和任务类型，只改增强强度。

### 最常调的四个参数

| 参数 | 含义 | 建议 |
|---|---|---|
| **扩增倍数**（`--times`） | 每张原图生成几张 | 55 张以内建议 5~8；100 张以上 2~3 |
| **旋转 ±度**（`--degrees`） | 随机旋转角度范围 | 零件姿态固定就设 0~10；姿态随意可到 30 |
| **缩放 ±比例**（`--scale`） | 随机缩放范围 | 小目标多时调小（0.2），否则 0.3~0.5 |
| **Mosaic 概率**（`--p-mosaic`） | 4 图拼接的概率 | 小数据集建议开 0.4~0.5；已做大量离线增强可降到 0.3 |

### 两个容易踩坑的参数

- **水平翻转概率 / 垂直翻转概率**（`--p-hflip` / `--p-vflip`）：**零件左右不对称时务必设为 0**。翻转会造出现实中不存在的姿态，模型学到错误特征。工业零件场景建议直接选「工业零件」预设。
- **随机擦除概率**（`--p-cutout`）：只会擦掉不覆盖任何目标的背景区域，是安全的；但小目标数据集建议调小或设 0。

### 三项提升鲁棒性的增强

这三项针对真实产线上的常见干扰，默认值偏保守，可按需开启：

| 增强 | 参数 | 模拟什么 | 建议 |
|---|---|---|---|
| **锐化** | `--p-sharpen` `--sharpen-amount` | 对焦波动 / 镜头老化 | 默认开 0.15。金属反光表面建议 `--sharpen-amount 0.3~0.5`，太强会放大高光噪点 |
| **椒盐噪声** | `--p-saltpepper` `--saltpepper-ratio` `--salt-ratio` | 传感器坏点 / 传输误码 | 默认开 0.10。只污染目标区域，背景不撒点 |
| **遮挡** | `--p-occlusion` `--occlusion-max` | 零件相互遮挡 / 纸箱遮挡 | **默认关**（0），需要时开 0.3~0.5 |

**遮挡增强的标注规则**（重要）：

- 遮挡后目标**残余可见面积**小于 `--min-side`/`--min-area` 阈值 → **丢弃该目标**（几乎全被盖住，留着就是错误标注）
- 否则**保留原框**——YOLO 检测任务中被遮挡目标仍应被检出，这是标准做法
- 仅对 **detection / pose** 生效；**分割和 OBB 不参与遮挡**，因为多边形和旋转角被遮后不再准确

实测覆盖率（`--occlusion-max` 与"被遮目标实际覆盖率"的对应关系）：

| `--occlusion-max` | 被遮目标覆盖率（中位 / 最大） |
|---|---|
| 0.2 | 13% / 20% |
| 0.35 | 23% / 35% |
| 0.6 | 39% / 61% |

> [!TIP]
> 遮挡参数是"**该目标最多被遮掉的面积比例**"。多目标图里只会随机挑 1~3 个目标遮挡，
> 其余目标不受影响——这是设计如此，不是 bug。

### 其它参数

<details>
<summary>点开看完整参数说明</summary>

**基础设置**

| 参数 | 说明 |
|---|---|
| `--val-ratio` | 源数据集没有 val 时，从 train 划出多少比例做验证集（默认 0.2，**验证集绝不增强**） |
| `--seed` | 随机种子，想让结果可复现就固定它 |
| `--limit` | 只处理前 N 张（调试用），留空 = 全部 |
| `--preview` | 除了界面预览，额外在输出目录的 `preview/` 里存 N 张预览图 |
| `--quality` | JPEG 保存质量，默认 95 |
| `--min-side` | 小于该像素边长的框会被丢弃（默认 2 像素，防止出现退化的极小框） |
| `--names` | 类别名，逗号分隔，覆盖 data.yaml 里的 |
| `--no-original` | 不把原图复制进新数据集（默认会复制，即 train = 原图 + 增强图） |
| `--allow-missing-labels` | 允许部分图片没有 `.txt` 标签（默认会报错拦截，防止标签路径填错） |
| `--overwrite` | 输出目录已存在时覆盖 |
| `--dry-run` | 只统计不写文件 |

**增强强度**

`--degrees` 旋转 ±度 · `--scale` 缩放 ±比例 · `--translate` 平移 ±比例 · `--shear` 剪切 ±度 · `--perspective` 透视强度（0~0.001）

**触发概率**（0 表示关闭）

`--p-mosaic` Mosaic · `--p-copypaste` Copy-Paste（仅分割） · `--p-hflip` 水平翻转 · `--p-vflip` 垂直翻转 · `--p-rot90` 90°旋转 · `--p-cutout` 随机擦除 · `--p-sharpen` 锐化 · `--p-saltpepper` 椒盐 · `--p-occlusion` 遮挡

**新增强的强度**

`--sharpen-amount` 锐化强度 0~1 · `--saltpepper-ratio` 噪点占目标像素比例 · `--salt-ratio` 白点占比 · `--occlusion-max` 单个目标最多被遮面积比例

</details>

## 五、增强完怎么训练

产物结构：

```text
<输出目录>/
├── images/train     ← 原图 + 增强图
├── images/val       ← 未增强的原图
├── labels/train
├── labels/val
└── data.yaml        ← 直接拿它训练
```

训练时把 `data` 指到这个 `data.yaml`：

```python
from ultralytics import YOLO

model = YOLO("yolo11n.pt")  # 分割用 yolo11n-seg.pt，旋转框用 yolo11n-obb.pt
model.train(
    data=r"<输出目录>/data.yaml",
    imgsz=[640, 480],
    epochs=200,
    batch=16,
    workers=0,
    device="0",
)
```

> [!IMPORTANT]
> **权重必须和任务匹配**：检测用 `yolo11n.pt`、分割用 `yolo11n-seg.pt`、
> obb 用 `yolo11n-obb.pt`、**关键点用 `yolo11n-pose.pt`**，用错会直接报错。

> [!TIP]
> `workers=0` 是 Windows 下的稳妥写法；`batch` 按显存调，建议 8 的倍数。

## 六、常见问题

<details>
<summary><strong>Q：报错「图片与标签数量不匹配」？</strong></summary>

说明标签路径填错了，或者只标注了一部分图片。报错信息会列出具体缺标签的文件名前几个。

检查这几点：

1. 标签目录是否和图片目录对应（`images` ↔ `labels`，`images/train` ↔ `labels/train`）；
2. 标签文件名是否与图片同名（`A1.jpg` ↔ `A1.txt`，注意别是 `A1.jpg.txt`）；
3. 标签是否还在别的盘 / 别的目录（标注工具导出时常这样）。

如果确实有部分图片不需要标注（纯背景），加 `--allow-missing-labels` 放行，
这些图会生成空标签（作为负样本训练，对降低误检其实有帮助）。

</details>

<details>
<summary><strong>Q：图片和标签不在同一套目录结构里，能用吗？</strong></summary>

能。这正是拆成两个输入项的目的 —— `--image-path` 和 `--label-path` 可以指向任意两个目录，
不同盘、不同命名都可以。

工具会自动去这些地方找 `data.yaml` / `classes.txt`：
图片目录、标签目录，以及它们各自往上 3 层。都找不到时用 `--names` 直接指定类别名，例如：

```bash
--names "U2"                # 单类别
--names "single,multiple"   # 多类别
```

</details>

<details>
<summary><strong>Q：输出目录改名后发现训练报错 images not found？</strong></summary>

`data.yaml` 里写的是生成时的绝对路径，改名后就失效了。

**解决办法**（任选其一）：

1. 把目录改回原名；
2. 重新跑一次增强，输出到新名字；
3. 手动把 `data.yaml` 里的 `path` / `train` / `val` 改成新路径。

</details>

<details>
<summary><strong>Q：统计显示实例数 0 / 空标签数等于图片数？</strong></summary>

这个数据集没标注。先标注（X-AnyLabeling），再转格式：

```bash
python json2yolo.py --src "你的数据集目录" --task detection
```

</details>

<details>
<summary><strong>Q：关键点数据集报错「需要确定关键点数量 / kpt_shape」？</strong></summary>

`pose` 任务必须在 `data.yaml` 里写明关键点数量，否则无法解析标签列数：

```yaml
kpt_shape: [5, 3]      # 5 个关键点，每个 3 维（x, y, 可见性）
```

如果每个关键点只标了 `x, y`（没有可见性），就写 `kpt_shape: [5, 2]`。
判断方法：标签每行列数 = `1`(类别) + `4`(框) + `K × ndim`。

</details>

<details>
<summary><strong>Q：关键点数据集开启翻转后，关键点好像"错位"了？</strong></summary>

这通常是因为 `data.yaml` 里**没有 `flip_idx`**。`flip_idx` 定义左右对称关键点的编号映射，
例如人脸 5 点 `flip_idx: [1, 0, 3, 2, 4]` 表示翻转后 0 号和 1 号互换身份。

不带 `flip_idx` 时，翻转只会镜像坐标而不会交换编号，模型会把"左眼"学到图像右侧去。
**两个选择**：

1. 在 `data.yaml` 补上 `flip_idx`（推荐）；
2. 把「水平翻转概率」「垂直翻转概率」都设为 0。

工具在 pose 任务下若无 `flip_idx` 且翻转概率非 0，会在日志里打印警告。

</details>

<details>
<summary><strong>Q：预览时框没跟着图转？</strong></summary>

正常情况框一定会跟着一起变换。如果明显错位：

1. 先确认 `--task` 选对了（9 列数据最容易选错）；
2. 再看框的坐标数：检测是 5 个数，分割是奇数个，obb 是 9 个，pose 是 `5 + K×(2或3)` 个。

</details>

<details>
<summary><strong>Q：auto 报「标签都是 9 列」错误？</strong></summary>

手动把任务类型选成 `obb` 或 `segment`。

</details>

<details>
<summary><strong>Q：参数调乱了想恢复？</strong></summary>

点「恢复默认」。另外界面会自动记住上次的参数，下次打开还是上次的设置（存在 `.augment_gui_last.json`）。

</details>

<details>
<summary><strong>Q：--times 是不是越大越好？</strong></summary>

不是。55 张的图 `times=5~8` 有明显收益；再往上模型会开始记忆合成图，反而学不到泛化特征。

</details>

## 七、其它脚本

| 文件 | 用途 |
|---|---|
| `augment_dataset.py` | 核心增强脚本，界面就是它的壳；所有参数定义在 `PARAM_SPEC`，命令行与界面共用这一份 |
| `augment_gui.py` | 图形界面本体 |
| `run_gui.pyw` | 双击启动器（无控制台 + 自动找对的解释器） |
| `json2yolo.py` | 把 X-AnyLabeling / LabelMe 的 `.json` 标注转成 YOLO `.txt` |
| `__init__.py` | 包定义，便于 `import augment_dataset as pkg` |

等价的命令行也能直接跑（界面底部的「等价的命令行」文本框会随参数实时显示，可直接复制）：

```bash
python augment_dataset.py \
    --image-path datasets/U2/images \
    --label-path datasets/U2/labels \
    --task detection --times 3 --out datasets/U2_aug
```

相对路径按「当前目录 → 本脚本目录 → 上级目录」依次查找，所以在 `ultralytics` 根目录下运行上述命令也能用。

> [!NOTE]
> 旧参数 `--src` 仍保留兼容：`--src datasets/U2` 会自动转换为
> `--image-path datasets/U2/images` 与 `--label-path datasets/U2/labels`，
> 并在终端打印转换结果。新脚本建议直接用两个新参数。
